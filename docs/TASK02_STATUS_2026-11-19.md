## حالة Sandbox المحلية

المضيف المحلي Ubuntu 24.04 ARM64. Android SDK Command-line Tools مثبتة (`sdkmanager` 22.0)، وكذلك `platforms;android-36` revision 2 و`build-tools;36.1.0` و`platform-tools` 37.0.3. أظهرت ملفات `source.properties` و`package.xml` الإصدارات المتوقعة واجتاز `android.jar` فحص ZIP. ملفات `adb` و`aapt` و`aapt2` من نوع Linux x86-64، لذلك لم تُشغّل على ARM64. قُبل `android-sdk-license` وحده محليًا، وما زالت تراخيص أخرى غير مقبولة.

Flutter وDart غير متاحين محليًا على PATH. يثبت manifest الرسمي أن Stable 3.50.0 على Linux يستخدم Dart x64 ولا يوفر حزمة Linux ARM64؛ archive الرسمي الذي نزّله runner هو `stable/linux/flutter_linux_3.50.0-stable.tar.xz` وبصمة SHA-256 `6ea2d806fd57269ae783e6788e2a81fc26eaad782f1e0d0ff38623bb765ff9f5`. لم يُشغّل ملف x64 على Sandbox. ## تشغيل GitHub Actions الفعلي

اكتمل تشغيل Android CI رقم 44737667246 في 2026-11-20 بنتيجة `success`، على commit `cac20ad419c22307fca3f9b0f4ba6be7dce0a16f`. استغرق نحو دقيقة و40 ثانية. استخدم runner `ubuntu-24.04` بمعمارية `x86_64`، ونظام Ubuntu `24.04.5` وصورة `20261116.133.1`. [5] [9]

نجحت خطوات checkout وTemurin JDK وقبول الترخيص المحدود والتحقق من Android SDK وتنزيل Flutter والتحقق من Java وSDK. الإصدارات التي أثبتها السجل الفعلي هي:

- Temurin JDK `21.0.13+9`.
- Flutter Stable `3.50.0`، Dart `3.14.0`، وملف Dart التنفيذي من نوع Linux x86-64؛ تحقق workflow من SHA-256 الرسمي قبل فك archive.
- Android Command-line Tools / `sdkmanager` `12.0`.
- `platforms;android-36` revision `2`، و`build-tools;36.1.0`، و`platform-tools` revision `37.0.3`.
- أُظهر سجل التراخيص اسم `android-sdk-license` وحده في مجلد licenses؛ ولم تُقبل تراخيص أخرى.

ثبت workflow actions الرسمية إلى SHA كامل: `actions/checkout` و`actions/setup-java` و`actions/upload-artifact`. [6] [7] [8]

تضمنت صورة runner حزم SDK أخرى موجودة مسبقًا، منها NDK وCMake ومنصات وأدوات بناء أخرى. يطلب workflow الحزم الثلاث المصرح بها فقط، ولم يطلب تثبيت NDK أو CMake أو Emulator. ظهور مكونات الصورة في قائمة `sdkmanager --list_installed` لا يعني أنها مطلوبة للمشروع ولا يعني قبول تراخيصها.

أظهر `flutter doctor -v` نتيجة Flutter سليمة، لكنه عرض تحذير Android بأن تراخيص أخرى غير مقبولة، وهو متوقع لأن الموافقة اقتصرت على `android-sdk-license`. كما أظهر نقص GTK و`eglinfo` لأدوات تطوير Linux desktop، وهي خارج نطاق بناء Android. أبقى workflow التحذيرات ظاهرة ولم يقبل تراخيص أو يثبت مكونات إضافية لإخفائها. اختتمت خطوة التحقق والـjob بنجاح مع هذه التحذيرات.

## حدود نجاح التشغيل والتحليل والبناء

لم يجد التشغيل `pubspec.yaml`. لذلك كانت خطوة `Project analysis, tests, and debug APK` وخطوة رفع APK artifact بحالة `skipped`. لم تُنفذ `dart format` أو `flutter analyze` أو `flutter test` أو `flutter build apk --debug`، ولم يُنتج APK. نجاح Actions يعني أن إعداد الأدوات والتحقق منها نجحا، ولا يعني نجاح تحليل أو اختبارات أو بناء TeleManager.

وجد runner أدوات عامة `Gradle 9.9.1` و`kotlinc-jvm 2.4.21`. هذه ليست إعدادات مشروع TeleManager. لا توجد ملفات Gradle wrapper أو `build.gradle` أو `settings.gradle` أو نسخ خاصة بالمشروع من `Android Gradle Plugin` أو `Kotlin Gradle Plugin` لتدقيقها، لذا لم يثبت التوافق أو بناء مشروع Kotlin/Android.

## Kotlin وGradle وسكربت الإعداد

لم يُشغّل `scripts/setup_toolchain.sh`؛ تمت مراجعته ساكنًا. على ARM64 ينفذ `apt-get update` ويثبت متطلبات النظام، ويتحقق من Command-line Tools وقد ينزلها إن كانت غائبة، ثم يخرج بالرمز `2` قبل تنزيل Flutter أو ضبط PATH في `.bashrc` أو تثبيت منصات SDK أو قبول التراخيص أو إنشاء مشروع أو إجراء اختبار أو بناء APK. وعلى x64 ينزل Flutter Stable المتغير وقت التشغيل بعد التحقق من SHA، لكنه لا يثبت حزم Android المطلوبة أو ينشئ scaffold أو يشغّل التحليل والاختبارات والبناء.
