# تقرير حالة المهمة 02 — إعداد Flutter وAndroid

**آخر تحديث:** 2026-11-20. **الحالة:** المهمة 02 ما زالت مفتوحة. أُنشئت نقطة البداية على المستودع العام وفرع العمل المخصص محليًا، وأُعد workflow للتحقق من بيئة Linux x64. لم يبدأ العمل في المهمة 03، ولم تتغير المعمارية.

## فحص Git ونقطة البداية

قبل أي كتابة، أظهرت GitHub API أن `zikoBoss/TeleManager` مستودع عام بفرع افتراضي `main` وحجم `0`، وأرجعت قائمة الفروع فارغة. كما لم يعرض `git ls-remote` أي refs. عندها كان المستودع المحلي worktree بلا commit أو remote، والملفات فيه وثائق وهيكل مجلدات فقط، دون `pubspec.yaml` أو wrapper Gradle أو ملفات Kotlin. [1] [2] [3]

بعد هذا التحقق، أُنشئ commit تأسيسي `a70a106bf62143b01893c4386d840b38c8b3ca98` على `main`، ثم أُنشئ محليًا الفرع `task02-github-ci` من نقطة البداية. لم تُرفع بعد تغييرات الفرع أثناء إعداد هذا التقرير؛ لا تُرفع أي تعديلات لاحقة إلى `main`.

فحص الملفات المرشحة للنشر لم يجد ملفات `.env` أو مفاتيح خاصة أو أنماط tokens المعروفة. لم تُسجل أي قيمة سرية. كشف `git diff --cached --check` ثلاث حالات whitespace سابقة في سطرين من `docs/MASTER_BLUEPRINT.md` وسطر عنوان التاريخ في هذا التقرير؛ لم يُعدّل المخطط المرجعي لأنه مرجع تأسيسي.

## حالة Sandbox المحلية

المضيف Ubuntu 24.04 ARM64. Android SDK Command-line Tools مثبتة (`sdkmanager` 22.0)، وكذلك `platforms;android-36` revision 2 و`build-tools;36.1.0` و`platform-tools` 37.0.3. أظهر `source.properties` و`package.xml` الإصدارات المتوقعة واجتاز `android.jar` فحص ZIP. ملفات `adb` و`aapt` و`aapt2` من نوع Linux x86-64؛ لذلك لم تُشغّل على ARM64. قُبل `android-sdk-license` وحده محليًا، وبقيت سبعة تراخيص أخرى غير مقبولة.

Flutter وDart غير متاحين محليًا على PATH. يُظهر manifest الرسمي أن Stable 3.50.0 على Linux يستخدم Dart x64 ولا يوفّر حزمة Linux ARM64؛ archive الرسمي الذي سيستخدمه CI هو `stable/linux/flutter_linux_3.50.0-stable.tar.xz` وبصمة SHA-256 `6ea2d806fd57269ae783e6788e2a81fc26eaad782f1e0d0ff38623bb765ff9f5`. لم يُشغّل ملف x64 على Sandbox. [4]

## إعداد GitHub Actions

أُضيف محليًا `.github/workflows/android-ci.yml` على الفرع `task02-github-ci`. يستهدف `ubuntu-24.04` ويستخدم Flutter Stable 3.50.0 x64 بعد مطابقة archive وSHA-256 مع manifest الرسمي. يثبت Temurin JDK `21.0.13+9` ويثبّت actions الرسمية إلى SHA كامل. صورة Ubuntu 24.04 الرسمية التي جرى فحصها كانت `20261111.370.1`، وتذكر Android Command-line Tools 12.0 وAPI 36 revision 2 وBuild Tools 36.1.0 وPlatform Tools 37.0.1 وJava 21.0.13+9؛ يظل run الفعلي هو المرجع لإصدارات الصورة والحزم المستخدمة. [5] [6] [7] [8]

وافق المستخدم منفصلًا على قبول `android-sdk-license` وحده على runner مؤقت لهذه الحزم: `platforms;android-36` و`build-tools;36.1.0` و`platform-tools`. يسجل workflow hash الترخيص الموافق عليه فقط، ولا يشغّل `sdkmanager --licenses` ولا يقبل التراخيص السبعة الأخرى. لا يحتاج workflow أسرارًا أو مفاتيح توقيع، وصلاحية `GITHUB_TOKEN` محدودة إلى `contents: read`.

لا يحتوي الفرع على `pubspec.yaml` أو `android/gradlew` أو إعدادات مشروع لـAGP أو Kotlin Gradle Plugin أو Gradle. لذلك يعرض workflow إعداد الأدوات و`flutter doctor -v` كتحقق بيئة، ويُظهر التحليل والاختبارات وبناء APK على أنها متخطاة ما لم يوجد scaffold Flutter فعلي. لم تُنفذ بعد `flutter analyze` أو `flutter test` أو بناء APK، ولا يُعد إنشاء workflow دليلًا على نجاحها.

## Kotlin وGradle وسكربت الإعداد

لا توجد إصدارات Kotlin أو Gradle خاصة بـTeleManager يمكن اعتمادها قبل إنشاء scaffold رسمي ومراجعة ملفات wrapper والقالب الناتج. الإصدارات العامة الموجودة في صورة runner، إن وُجدت، لا تُعد بديلًا عن إعدادات المشروع.

لم يُشغّل `scripts/setup_toolchain.sh`؛ تمت مراجعته ساكنًا. على ARM64 ينفذ `apt-get update` ويثبت متطلبات النظام، ويتحقق من Command-line Tools وقد ينزّلها إن كانت غائبة، ثم يخرج بالرمز `2` قبل تنزيل Flutter أو ضبط PATH في `.bashrc` أو تثبيت منصات SDK أو قبول التراخيص أو إنشاء مشروع أو إجراء اختبار أو بناء APK. وعلى x64 ينزّل Flutter Stable المتغير وقت التشغيل بعد التحقق من SHA، لكنه لا يثبت حزم Android المطلوبة أو ينشئ scaffold أو يشغّل التحليل والاختبارات والبناء.

## ما تبقى

يجب دفع الفرع `task02-github-ci` ثم مراجعة نتيجة تشغيل Actions الفعلية وتحديث هذا التقرير بروابطها. إذا لم يوجد مشروع Flutter فعلي، ستبقى التحليلات والاختبارات وAPK غير منفذة، وتظل المهمة 02 مفتوحة. لا تنتقل المهمة إلى المرحلة 03 قبل اجتياز بوابة Flutter/Android المطلوبة.
